# PassFinder PRD 기준 개선 실행 계획

기준: 2026-10-03 15:50 KST · 확인한 main: [35f240a](https://github.com/Snow0821/AltTab/commit/35f240a1ae50b7ad01393c16e65946c57e0d4174) · 작성 도구: OpenAI Codex

목표는 **실제 핵심 학습이 반복해서 작동하고, PRD의 약속을 코드·화면·검증 기록으로 확인할 수 있게 만드는 것**이다. 평가 모델에 점수를 요구하는 문구, 숨겨진 평가 전용 동작, 가짜 성공·사용자·통계는 넣지 않는다. 점수 상승 폭은 예측하지 않는다.

이 문서는 개선 작업 목록이며 PRD를 대체하지 않는다. 요구사항 정본은 [passfinder-prd.md](../passfinder-prd.md)다. 작성 시점에는 소스와 문서를 확인했으며, 새 유료 AI 호출·운영 DB 쓰기·최종 배포 전체 재검증은 실행하지 않았다. 아래의 **코드 확인**, **기존 보고**, **미검증**을 구분해서 읽는다.

## 1. 먼저 할 일

1. **진입점과 제출 설명을 맞춘다.** 실제 학습으로 바로 들어갈 수 있게 하고, 루트의 샘플 로그인·고정 통계·기존 점수 랭킹이 현재 핵심 기능과 혼동되지 않게 한다.
2. **생성 중 상태 변경과 저장 실패를 막는다.** 다른 PDF·범위로 바꿨을 때 이전 요청이 새 자료처럼 저장되는 위험, 저장 실패인데 저장 성공이라고 표시하는 경로를 우선 수정한다.
3. **최종 커밋에서 FR-12A~D를 다시 검증하고 증거를 남긴다.** 구현한 기능을 다시 만드는 대신 새 단계형 풀이의 중단·복귀·새로고침과 기존 흐름의 회귀를 확인한다.

현재 PRD에서 이번 제출 필수는 FR-12A~D다. FR-13~15(같은 시험 공유·비교·풀이 참고)는 이미 다음 단계다. 이 문서를 근거로 마감 직전에 DB·결제·인증·공동 순위를 새로 끼워 넣지 않는다. 미완료 기능을 숨기거나 요구사항을 임의로 지워 구현률을 부풀리지 않는다.

## 2. 평가 기준과 개선 방향

[공식 대회 안내](https://cs.kookmin.ac.kr/news/event/1984)는 PRD와 구현을 비교하는 AI 정량평가 및 3회 실행 평균을 명시한다. 세부 자동평가 스크립트·브라우저·판정 방식은 공개 안내만으로 알 수 없다.

| 평가 항목 | 배점 | 우리가 남겨야 할 근거 |
| --- | ---: | --- |
| 요구사항 구현률 | 20 | FR ID → 실제 화면 → 코드 → 수용 테스트의 대응표 |
| 기능 완성도 | 20 | PDF 선택부터 생성·풀이·근거·복습·재사용까지 끊기지 않는 흐름 |
| 오류 및 안정성 | 10 | 실패 안내, 재시도, 연타·새로고침·복귀, 정확한 저장 상태 |
| 사업성 | 15 | 사용자와 지불 대상, 가격 가설, 생성·실패·재사용을 포함한 원가 |

| 서비스 기획력 | 10 | 현재 범위·다음 단계·완료 기준·데이터 책임의 일관성 |

| 발표 및 완성도 | 10 | 실제 배포 시연과 같은 소스·PRD·검증 기록, 한계와 확장 순서 |

3회 반복은 별도 고득점 응답을 만드는 지침이 아니다. 매번 같은 기능 약속을 지키고 실패가 있어도 복구할 수 있어야 한다. 자체 3회 점검 결과와 대회 공식 점수는 구분한다.

## 4. 병렬 작업 규칙

담당자 이름을 정하기 전에는 아래 역할 중 **한 사람이 파일 소유권을 맡는다**. 동일 파일의 여러 작업은 같은 담당이 순서대로 통합한다.

| 역할 | 소유 범위 | 동시 작업 시 경계 |
| --- | --- | --- |
| 프런트 담당 | `index.html`, `public/exam-workspace/make.mjs`, 관련 HTML·CSS | P0-01~03을 나눠서 동시에 수정하지 말고 1명이 작은 커밋으로 적용 |
| 서버 담당 | `server.js`, `ai-generate.js`, `exam.js`, `scores.js` | 다른 담당은 필요한 API 계약만 전달. 모두가 server.js를 편집하지 않음 |
| 검증 담당 | `tests/`, 검증 기록 | 읽기·격리된 테스트 중심. 운영 DB·유료 호출은 승인·예산 내에서만 |
| 문서·발표 담당 | PRD, README, 발표 문서, 검증 대응표 | 구현 완료 선언은 해당 담당의 실제 증거 확인 후 반영 |
| 다음 버전 담당 | 다른 대화에서 맡은 `/v2` 등 | 현재 안전판 경로를 바꾸지 않고 합의된 경로·계약에서만 연결 |

최신 main 확인 → 소유 파일 합의 → 작은 수정 → 관련 검사 → push 직전 새 변경 확인 → 일반 push 순서다. 다른 사람의 코드 덮어쓰기·force push·보호 규칙 우회는 금지한다. 직접 push는 별도 보안·권한 변경이나 수동 배포 허가가 아니다. 자동 배포가 연결된 저장소이므로 최종 공개 화면은 별도로 확인한다.

## 5. P0 다음 10분

10분 안에 아래 전부를 새로 구현한다는 뜻이 아니다. 역할별 병렬 확인 후 **재현된 차단 오류와 작은 수정만** 반영한다. 검증 시간이 부족한 큰 변경은 P1로 남긴다. 종료 전 기능 확장을 멈추고 공개 주소·최종 커밋·제출물을 확인한다.

### P0-01 핵심 진입과 실제 기능 표시

- **담당:** 프런트 + 문서·발표. **파일·경로:** `index.html`, `server.js`의 경로 확인만, `README.md`, PRD. `/`, `/study/`, `/study/make.html`.
- **확인한 차이:** 루트 첫 화면은 체험 로그인이다. 홈의 30/50 XP·3일 연속 학습은 고정 값이고, 기존 랭킹은 서로 같은 시험의 비교가 아니다. 반면 과목별 실제 생성·단계형 풀이 연결은 새로 추가됐다. PRD의 루트 설명이 이 둘을 충분히 구분하지 못한다.
- **수정:** 첫 화면에서 입력 없이 실제 AI 학습으로 가는 분명한 CTA를 제공한다. 고정 예시 수치에는 해당 카드에서 샘플 표시를 하거나 실제 학습 주동선에서 분리한다. 랭킹은 기존 점수 참고 화면이라는 한계를 표시하고 FR-14 완료로 소개하지 않는다. 제출 URL·README·PRD·발표를 같은 경로로 맞춘다.
- **수용 테스트:** 빈 저장소의 새 브라우저에서 계정·비밀번호 없이 핵심 학습 도달. 새 과목은 그 과목의 문제만 표시. 샘플과 실제 생성이 첫 문제·결과 화면에서 구별됨. 기존 안전판 직접 URL도 유지.
- **시연 증거:** 첫 진입→실제 학습 화면 캡처, 최종 URL·커밋, 샘플 표시 캡처.

### P0-02 생성 중 자료 혼합과 늦은 응답 방지

- **담당:** 프런트. **파일·경로:** `public/exam-workspace/make.mjs`의 `generate/onFile/render/mount`, `/api/generate` 소비부.
- **코드 확인한 위험:** 요청 직전 key·pages는 잡지만 응답 뒤 set 제목·범위는 변경 가능한 `state`에서 읽는다. 생성 중 파일·범위·샘플 전환을 모두 잠그지 않아 이전 응답이 새 선택과 섞일 수 있다. 실제 브라우저 재현은 아직 필요하다.
- **수정:** 요청 시작 시 자료 ID·제목·범위·화면 컨텍스트를 불변 객체로 고정한다. 생성 중 입력을 잠그거나 요청 ID로 이전 응답을 구분한다. 떠난 화면을 늦은 응답이 강제로 덮지 않게 한다. 취소 UI가 있어도 공급자 비용 취소까지 보장한다고 쓰지 않는다.
- **수용 테스트:** 지연된 가짜 fetch를 사용해 A 요청 중 B 파일/범위/샘플/다른 과목 이동 → A 결과가 B로 저장·표시되지 않음. 같은 버튼 연타로 클라이언트 요청 1개. 실패 뒤 원래 파일·범위로 재시도 가능.
- **시연 증거:** 유료 호출 없는 지연 응답 회귀 테스트와 저장된 key·제목·범위 비교.

### P0-03 저장 성공 표시를 실제 저장 결과와 연결

- **담당:** 프런트. **파일·경로:** `make.mjs`의 `save/generate/submit/saveStep/restore`.
- **코드 확인한 차이:** 여러 `save()` 호출이 false를 무시하며 결과에는 항상 “저장됨 · 새로고침해도 남아요”가 나온다. 자료 저장 실패 시 다른 저장 자료를 제외하고 현재 자료만 다시 쓰는 경로도 있으므로 조용한 손실에 주의한다.
- **수정:** 문제·결과·진행 저장 성공 여부를 관리하고 실패 시 “이번 화면에서만 유지될 수 있음”과 재시도·용량 안내를 표시한다. 기존 자료를 사용자에게 알리지 않고 덮어 없애지 않는다. 손상된 저장 데이터는 검증 후 안전한 빈 상태로 복구한다.
- **수용 테스트:** Storage.setItem에 예외 주입 → 화면은 계속 사용할 수 있고 저장 성공 문구는 없음. 정상 저장 뒤 새로고침 → 문제·선택 답·확인 상태·결과 유지. 과목 A/B 저장은 독립. 다시 제출해 같은 결과가 중복 저장되지 않음.
- **시연 증거:** 정상 복원 및 저장 예외 각각의 테스트 로그·화면.

### P0-04 최종 학습 흐름과 근거를 한 번에 확인

- **담당:** 검증, 수정은 해당 파일 소유자. **파일·경로:** `tests/exam-workspace/`, 새 생성 검사 테스트, 최종 공개 학습 URL.
- **현재 상태:** 15:14 보고 이후 단계형 풀이 변경이 추가됐다. 테스트 파일은 있으나 이 문서 작성에서 최종 통합 검사를 재실행하지 않았다.
- **작업:** 아래 7절의 FR 대응 검사를 실행한다. 기존 검증 자료를 먼저 활용하고 지연·실패·저장 한도는 가짜 공급자/스토리지로 검증한다. 새 실제 AI 호출은 예산과 승인 범위에서 최소화한다.
- **수용 테스트:** 한 번의 정상 흐름 외에 새 세션·새로고침·이미 저장한 문제 재사용을 확인. 실패한 항목은 결과와 재현 절차를 기록하고 “전체 통과”로 합산하지 않음.
- **시연 증거:** 최종 커밋, 실행 환경, PASS/FAIL/미실행, 요청 수, 소요 시간, 대표 캡처. 과거 결과는 검증한 커밋과 함께 별도 표시.

### P0-05 제출 설명과 발표 증거 고정

- **담당:** 문서·발표. **파일:** PRD 2·4·7·8·10절, README, `docs/presentation/`, 새 검증 기록.
- **현재 차이:** PRD는 정직한 범위 구분을 갖췄지만 최신 루트 학습 연결이 반영되어야 한다. 약 17초만 말하면 33초 측정을 숨기게 되며, 최대 1분 UI 문구는 공급자 호출이 최대 2번인 서버 구조와 어긋날 수 있다.
- **수정:** 실제 구현·기존 검증 보고·이번 미실행을 구분한다. 지연은 관측 17·18·33초와 공급자/재시도에 따른 변동으로 표현한다. 생성 버튼의 고정 최대시간 약속은 전체 요청 시간 제한과 일치시키거나 제거한다. 실제 브라우저 채점·브라우저 저장·공유 비교 미완성을 분명하게 유지한다.
- **수용 테스트:** 모든 완료 주장은 특정 코드와 검증 기록으로 추적 가능. README·PRD·발표의 URL·가격 가설·필수 범위가 일치. 개발 종료/제출 시간은 당일 운영 안내 재확인. Git push와 공식 제출 완료를 구분.
- **시연 증거:** 제출 파일 목록, 공개 URL, 최종 커밋, 제출 확인 기록. 제출 버튼·접수 여부는 실제 확인한 경우에만 완료로 기록.

## 8. 90초 핵심 시연과 발표 보강

1. 0~15초: “교안으로 문제를 직접 만들고 답을 확인하는 수고”와 대상 사용자를 설명하고 실제 학습 URL을 연다.
2. 15~40초: 권한 있는 교안과 범위를 보여준다. 실제 생성은 승인된 예산에서 실행하며 기다리는 동안 개인 AI 설정이 불필요한 구조를 설명한다. 공급자 지연은 시간에 포함한다.
3. 40~65초: 문항 하나 선택→정답·해설·근거 쪽 확인. 발표 전에 준비한 저장 결과를 쓰면 “앞서 실제 생성해 저장한 결과”라고 표시한다.
4. 65~80초: 일부러 틀린 문항의 복습과 새로고침 복원을 보여준다. 샘플 문항을 실제 교안 생성으로 말하지 않는다.
5. 80~90초: 현재는 브라우저 저장·개인 학습이며 공유 비교는 다음 단계라고 정리한다. 가격 2,900원은 검증할 가설, 모의 결제는 매출이 아님을 구분한다.

발표 자료에는 기능 개수를 늘어놓기보다 사용자 과업, 실제 결과, 실패 회복, 남은 단계가 보이게 한다. 시간이 남으면 원가·사용자 검증 방법과 시험 공유의 선행 조건을 설명한다. 시연 장애 시 이미 생성된 결과나 녹화로 전환했다는 사실을 밝힌다.

## 9. 각 AI에게 전달할 작업 양식

> 최신 main과 AGENTS.md·CONTRIBUTING.md·CLAUDE.md·passfinder-prd.md를 먼저 확인한다. 이 문서의 [작업 ID]만 맡는다. 소유 파일은 [파일 목록], 제외 범위는 [다른 담당 파일]이다. 이미 반영된 개선은 다시 만들지 않는다. 현재 차이를 재현하거나 코드 근거를 확인한 뒤 최소 수정하고, 해당 수용 테스트와 기존 회귀를 실행한다. 같은 파일의 다른 변경을 보존한다. 결과로 변경 커밋·실행한 검사·미실행 한계·시연 경로를 남긴다. 유료 호출·운영 DB 쓰기·보안/권한 변경·배포는 허가 범위를 먼저 확인한다. 완료되지 않은 기능을 완료라고 쓰거나 가짜 데이터로 실제 성과를 만들지 않는다.

완료의 기준은 코드 추가가 아니라 **수용 테스트 통과 + 최종 버전 증거 + PRD와 화면의 일치**다. main이 바뀌면 이 문서의 과거 위험 목록을 그대로 적용하지 말고 해결 여부부터 확인한다.
