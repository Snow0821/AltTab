# passfinder 시험 대비 학습 서비스 PRD

이 문서는 기존 passfinder PRD의 사업 가정과 요구사항을 검토한 팀 수정안이다. 현재 구현과 대조가 끝난 제출본은 아니다. Mint 검토와 팀의 범위 확정 전에는 기존 PRD·역할 분담안을 자동으로 대체하지 않는다. 채택 후에는 기존 PRD에 통합하고 기준 문서를 하나로 유지한다.

핵심 변경은 사용자 AI·MCP 연결을 서버의 학교 AI API 호출로 바꾸고, 월 2,900원 구독과 총 20달러 개발·시연 예산을 적용하는 것이다. 학생은 별도 AI 계정 없이 웹에서 문제를 만든다. 기존 자료 처리·화면 작업은 재사용하고, MCP 담당은 개념·문항 생성 API로 작업 범위를 조정해야 한다. 현재 [팀 분담안](../team-work-plan.md)의 서버 생성형 AI 제외 방침과 달라지는 제안이므로 관련 설계와 함께 검토한다.

작성일: 2026-10-03. 현재 상태: 요구사항 수정안 작성. 실제 서비스 전체 동작과 공개 배포는 미검증이다. 사용자에게 보고된 로컬 PDF 업로드 상태를 전체 기능 완료로 간주하지 않는다.

가격과 비용 구조: 학생이 passfinder에 월 2,900원을 지불하고, passfinder 서버가 운영자의 API 키로 생성형 AI를 호출한다. 학생의 별도 AI 계정·API 키·MCP 연결은 요구하지 않는다. 아래 월 사용 한도는 원가 측정 전의 제안값이며, 수익성이 검증된 제공량이 아니다.

## 1. 한 줄 소개

passfinder는 대학생이 교안에서 연습문제를 준비하고 공부 순서를 정하는 수고를 줄이는 서비스다. 웹에서 자동 생성한 문제를 개념별 학습 단계에 저장하고, 5문제씩 풀면서 틀린 개념과 근거 페이지를 다시 확인한다.

이번 제출의 핵심 흐름은 **PDF 등록 → AI 문제 자동 생성 → 5문제 풀이 → 오답 복습 → 월 구독 체험**이다. 학생은 웹 안에서 학습 준비와 풀이를 끝낸다.

## 2. 문제 정의

### 해결할 불편

시험을 준비하는 학생은 교안을 읽는 것 외에도 개념을 나누고, 연습문제를 만들고, 답을 확인하고, 틀린 부분을 다시 찾는다. 이 준비와 정리 작업 때문에 실제로 문제를 풀며 공부하기까지 여러 행동이 필요하다.

이번 서비스는 다음 행동을 줄이는 데 집중한다.

| 현재 행동 | 서비스에서 제공할 결과 | 확인 방법 |
| --- | --- | --- |
| 교안을 보며 공부 순서를 직접 정함 | 근거 페이지가 있는 개념별 학습 단계 | 처음 보는 학생이 다음 공부할 개념을 찾는지 관찰 |
| AI 대화에서 문제를 복사하고 정답을 따로 관리함 | 웹에서 바로 풀고 기록을 이어감 | 대화 내용을 수동 복사하지 않고 첫 문제를 푸는지 확인 |
| 오답에 해당하는 교안 부분을 다시 찾음 | 오답 설명과 근거 페이지를 함께 표시 | 결과 화면에서 해당 페이지를 찾는 시간 측정 |

학생의 지불 의사와 시간 절감 효과는 아직 확인하지 않았다. 시험이 중요하다는 사실만으로 서비스 수요나 유료 전환을 확정하지 않는다. 성적 향상, 실제 시험 출제 확률, 합격을 보장하지 않는다.

### 성공 기준

제품 성공 기준은 학생이 자신의 자료로 첫 학습을 끝내고, 틀린 개념으로 돌아갈 수 있는 것이다. 사업 검증 기준은 이 경험에 대한 실제 지불 의사와 반복 사용이다. 테스트 결제 성공은 매출의 증거가 아니다.

대회에서는 사업성 15점, 문제 해결력 10점과 함께 PRD와 실제 서비스의 대조 평가 50점이 적용된다. 따라서 기능 축소뿐 아니라 사용 가치와 동작 증거를 함께 확보한다. 근거: [대회 공식 안내](https://www.knowverse.net/previews/kookmin_vibe_guide/index.html), 2026-10-03 확인.

## 3. 타깃 사용자

주요 사용자와 구매자는 PDF 교안으로 시험을 준비하는 대학생이다. 초기 검증 대상은 공학계열 학생 5명으로 잡되, 별도 AI 도구를 쓰지 않는 학생도 포함한다. 이는 모집 계획이며 확보한 사용자 수가 아니다.

처음에는 개인 학습으로 완결한다. 다른 학생의 가입이나 검수를 기다리지 않아도 사용할 수 있어야 한다. 같은 과목의 공동 문제은행은 개인 학습의 만족도와 권리 처리 방식을 확인한 뒤 검토한다.

첫 방문에는 로그인과 자료 등록만 필요하다. 웹에서 학습 준비를 누르면 서버가 문제를 생성한다. 이후에는 저장된 문제를 바로 이어서 푼다. AI 호출 비용은 구독료에 포함되며 학생에게 별도 API 요금을 청구하지 않는다.

## 4. 해결 방법과 차별점

### 제공 가치

passfinder가 호출한 생성형 AI가 개념과 문제를 만들고, passfinder는 이를 다시 찾을 수 있는 학습 단계와 풀이 기록으로 관리한다. 학생은 매번 문제를 새로 만들거나 복사하지 않고 이어서 공부한다. 오답에는 근거 페이지를 표시한다.

문제 생성이나 복습 기능만으로 차별성을 주장하지 않는다. Knowt는 무료 학습 모드와 협업, 제한된 AI 기능을 제공한다고 안내한다. 따라서 우리의 검증 대상은 특정 교안으로 학습을 준비하고 이어가는 과정이 더 간단한지다. 근거: [Knowt 무료 요금제 안내](https://help.knowt.com/en/articles/16905163-what-s-included-in-the-free-plan-for-students), 2026-10-03 확인.

### AI 처리 원칙

- 개념 추출·문항 생성: 서버가 운영자의 API 키로 외부 생성형 AI를 호출한다. 모델을 직접 학습하거나 자체 호스팅하지 않는다. 공급자와 모델은 실제 연동·비용·품질 확인 후 확정한다.
- 서버 처리: PDF 텍스트 추출, 페이지 정보 저장, 생성 요청·사용량 관리, 출력 형식 검사, 학습 기록, 구독 판정을 담당한다. 이번 범위는 짧은 PDF의 페이지 구분 텍스트를 입력하므로 별도 임베딩 검색을 필수로 두지 않는다.
- 정답 판정: 이번 제출은 정답이 하나인 객관식만 제공한다. 서버가 저장된 정답 ID와 선택한 ID를 비교한다.
- 품질 표시: 형식 검사와 출처 확인을 통과한 문항도 사실적 정확성이 보장되는 것은 아니다. 화면에는 AI 생성 문항임을 표시하고 근거 페이지와 문항 제외 기능을 제공한다.
- 공부 순서: AI가 제출한 선수 개념 관계를 우선한다. 교안의 등장 순서로 동점을 정한다. 출제 확률이나 검증되지 않은 중요도 점수를 표시하지 않는다.

## 5. 핵심 기능과 완료 기준

사용자에게 보이는 핵심 기능은 자료 등록, 학습 준비, 문제 풀이, 오답 복습, 구독 체험이다. 구현 추적을 위해 원본 PDF의 필수 FR-01~06 번호를 유지한다. 아래 기준은 구현 목표이며 완료 보고가 아니다.

### FR-01 자료 등록

이메일 로그인 후 과목명·교수명·학기·시험 구분을 입력해 개인 과목을 만든다. 다른 사람의 같은 이름 과목과 자동으로 합치지 않는다.

- 이번 범위는 과목당 PDF 1개, 1KB 이상 10MB 이하, 50페이지 이하, 추출 본문 30,000자 이하의 텍스트 PDF다. 제한은 화면에 업로드 전에 표시한다. 본문 한도를 넘으면 범위를 나눠 올리도록 안내하며 몰래 잘라서 출제하지 않는다.
- 업로드 중, 분석 중, 준비 완료, 실패 상태를 구분한다. 준비 완료 후 파일명·페이지 수·추출된 글자 수를 표시한다.
- 다른 형식, 빈 파일, 크기·페이지·본문 길이 초과, 암호화 PDF, 텍스트를 추출할 수 없는 PDF는 사유를 표시한다. 실패 파일은 문제 생성에 쓰지 않는다.
- 같은 과목에 동일한 파일을 다시 올려도 자료를 중복 생성하지 않는다. 다른 파일 교체와 자료 병합은 이번 범위 밖이다.
- 서버 처리 실패 시 재시도할 수 있다. 동일 자료의 성공한 처리 결과는 재사용한다.
- 타인의 과목·파일은 URL을 알아도 열거나 수정할 수 없다. 로그아웃 상태에서 등록할 수 없다.

완료 확인: 정상 PDF 등록과 상태 변화, 중복 업로드, 잘못된 파일, 다른 계정 접근을 확인한다. 성능 검사는 팀이 준비한 10페이지 텍스트 PDF와 배포 환경을 기록하고 준비 완료까지 120초 이내를 목표로 측정한다. 모든 50페이지 파일이 같은 시간에 처리된다고 주장하지 않는다.

### FR-02 웹에서 학습 준비

- 과목 화면의 학습 준비 버튼을 누르면 서버가 페이지 번호를 붙인 교안 텍스트를 생성형 AI에 보내 개념을 추출한다. 별도 AI 계정이나 연결 설정을 요구하지 않는다.
- 계정당 무료 체험은 PDF 1개에서 개념 목록과 첫 단계 5문제다. 과목을 새로 만들어도 무료 제공량을 초기화하지 않는다.
- 생성 결과는 개념 이름, 300자 이내 설명, 근거 페이지, 선수 개념을 포함하며 최대 10개 개념으로 구성한다.
- 없는 페이지·개념을 참조하거나 선수 관계가 순환하면 성공으로 저장하지 않는다. 사유를 표시하고 허용된 요청 한도 안에서 다시 시도할 수 있다.
- 개념 순서를 확정하면 FR-04에 같은 순서로 표시한다. 풀이가 시작된 과목의 개념 구조 변경은 이번 범위에서 막는다.
- 생성 중에는 현재 상태를 표시한다. 중복 클릭·새로고침으로 같은 작업을 다시 호출하지 않는다. 한 계정에서 생성 작업 하나만 동시에 실행한다.
- API 인증·잔액·호출 제한·시간 초과 오류가 발생하면 실패 상태와 다시 시도할 방법을 표시한다. 준비된 예시로 바꿔 성공했다고 표시하지 않는다.
- 실패한 요청에도 공급자 비용이 발생할 수 있으므로 요청 횟수와 제공된 토큰 사용량을 기록한다. 비용을 숨기지 않되 비밀값은 기록하지 않는다.

완료 확인: 브라우저에서 PDF를 올리고 실제 생성형 AI로 개념을 만든다. 다른 AI 앱 없이 첫 단계 준비까지 진행되는지 확인한다. 공급자·모델·호출 결과·사용량을 증거로 남긴다.

### FR-03 문제 자동 생성과 저장

- 서버는 해당 개념의 근거 페이지를 생성형 AI에 보내 객관식 5문제를 요청한다. 다른 개념은 학생이 학습을 시작할 때 생성하고 같은 문제를 반복해서 생성하지 않는다.
- 각 문항은 질문, 서로 다른 선택지 4개, 정답 선택지 ID 1개, 해설, 자료 ID, 근거 페이지를 포함한다.
- 서버는 형식과 참조 자료의 존재를 검사한다. 정답 누락·중복 선택지·다른 과목 근거는 저장하지 않고 오류 사유를 반환한다.
- 같은 과목에서 공백을 정규화한 본문이 같은 문항은 중복으로 저장하지 않는다. 의미가 비슷한 문항을 전부 판별한다고 주장하지 않는다.
- 한 작업에서 유효한 5문제가 준비됐을 때 함께 저장한다. 부족하면 학습 시작을 막고 재시도를 안내한다. 5개보다 많은 결과를 무제한 저장하지 않는다.
- 무료 체험 이후 생성은 유효한 구독과 남은 사용량이 있어야 한다. 한 과목은 최대 10단계·50문제, 전체 계정은 FR-06의 기간 한도를 함께 적용한다.
- 같은 문제를 다시 풀거나 해설을 보는 데 생성형 AI를 다시 호출하지 않는다. 문항 제외 후 교체 생성도 요청 횟수와 생성 문항 한도에 포함한다.
- 다른 학생 검수와 운영자 승인은 필요하지 않다. 이 제출 버전은 개인 문제만 사용한다.

완료 확인: 실제 API로 두 개념의 문제를 생성한다. 무료 상태의 두 번째 개념 생성은 차단되고, 모의 구독 후 허용되는지 확인한다. 생성 결과 재조회가 새 API 호출을 일으키지 않는지 확인한다.

### FR-04 학습 단계와 다음 행동

- 개념 하나를 학습 단계 하나로 표시한다. 번호, 개념명, 근거 페이지, 준비 상태, 통과 여부가 보인다.
- 첫 단계부터 시작한다. 앞 단계를 통과하면 다음 단계에 도전할 수 있다. 무료 사용자는 체험 과목의 첫 단계만 풀 수 있다. 구독 중 생성한 기존 문제의 재풀이는 만료 후에도 FR-06 기준으로 유지한다.
- 잠긴 단계는 앞 단계 미통과, 구독 필요, 생성 중·실패, 사용량 소진 중 해당 사유를 보여준다. 서버도 같은 규칙으로 접근을 검사한다.
- 결과 화면의 다음 단계 버튼은 가능한 행동으로 연결한다. 문항이 없으면 문제 만들기 버튼을, 생성 실패 시에는 재시도 버튼을 보여준다. 생성 권한이 없으면 구독 또는 사용량 안내를 연다.
- 새로고침과 재로그인 후 진행 상태가 유지된다. 진행률은 통과 단계 수를 전체 개념 수로 나눈 값이다. 개념이 없으면 진행률 대신 준비 안내를 표시한다.

완료 확인: 두 개념 이상으로 첫 단계 준비, 통과, 다음 단계 접근, 새로고침 후 기록 유지를 확인한다.

### FR-05 풀이·해설·오답 복습

- 한 단계의 서로 다른 5문제를 한 문제씩 표시한다. 선택 전에는 제출 버튼이 비활성화된다.
- 답을 제출하면 서버가 판정한 정오답, 정답, 해설, 근거 페이지를 표시한다. 제출 전에는 정답을 브라우저에 보내지 않는다.
- 원본 PDF의 지정 페이지를 확인할 수 있는 보기를 제공한다. 자료에 접근할 수 없으면 오류를 표시하고 정답 근거를 지어내지 않는다.
- 처음 제출한 5개 답 중 4개 이상이 맞으면 통과한다. 결과 화면에 정답 수와 틀린 문항을 보여준다.
- 오답 다시 풀기는 학습용이다. 같은 회차의 원래 점수를 올리거나 통과로 바꾸지 않는다. 새 회차를 시작하면 다시 평가한다.
- 각 문항의 오류 표시 버튼을 누르면 본인 학습에서 제외한다. 근거와 다른 문제를 다시 학습하지 않도록 하고, 유효 문항이 5개 미만이면 재생성을 안내한다. 기존 풀이 이력은 남긴다.
- 동일 답안 재전송과 결과 화면 새로고침으로 풀이 기록이 중복되지 않는다. 중단 후 재개 시 같은 회차의 제출 답안을 복원한다.
- 주관식, 3단계 난이도, XP, 연속 학습, 시간 간격에 따른 복습 자동 예약은 포함하지 않는다.

완료 확인: 4/5 통과와 3/5 재도전, 오답 재풀이, 문항 제외, 중복 제출, 중단 후 재개를 확인한다. 5개 정답 모두를 임의로 성공 처리하지 않는다.

### FR-06 월 2,900원 구독 체험

- 상품은 계정 단위 월 2,900원 구독 한 종류다. 과목마다 추가 결제를 요구하지 않는다. 학생의 별도 AI 요금은 없다.
- 제출 버전의 모의 구독은 한 이용 기간을 30일로 정한다. 실제 자동 갱신·청구·해지는 구현 범위 밖이다. 가격 화면에 월 가격, 체험 기간, 실제 청구 없음과 자동 갱신 없음을 함께 표시한다.
- 제공량 제안은 기간당 새 PDF 3개, 생성 문항 150개다. 과목당 자료·개념 한도는 FR-01~03을 따른다. 기존 문제 풀이와 오답 확인에는 생성량을 차감하지 않는다.
- 비용 제한을 위해 무료 계정은 전체 생성 API 요청 최대 4회, 구독 기간에는 최대 40회로 제한한다. 개념 생성·문제 생성·교체·재시도 모두 요청 횟수에 포함한다. 성공한 문항만 문항 한도에서 차감하지만 실패 요청도 요청 횟수에는 포함한다.
- 요청 한도와 남은 PDF·문항 수를 구독 화면에 표시한다. 기본 모델과 입력·출력 한도는 9절의 20달러 예산 설정을 따른다. 실제 호출과 토큰 계수 방식의 검증은 출시 조건이다.
- 무료 체험과 구독 제공량은 별도 집계한다. 기존 체험 자료를 이어서 쓸 수 있으며 새 자료로 중복 차감하지 않는다. 구독 기간의 개념당 5문항 생성은 남은 제공량이 5개 이상일 때 시작한다.
- 서버가 생성 요청 전에 사용량을 원자적으로 예약해 동시 요청의 한도 초과를 막는다. 성공 시 문항 사용량을 확정하고, 실패 시 문항 예약을 해제한다. 이미 호출한 요청 횟수는 되돌리지 않는다.
- 사용자가 모의 구독을 확인하면 서버가 모의 주문과 이용 기간을 한 번만 생성한다. 재전송으로 기간이나 제공량이 늘지 않는다. 실패하면 구독을 부여하지 않는다.
- 만료 기준은 서버 시각이며 시작 후 30일이다. 만료 후 새 자료 분석과 추가 생성을 막지만 이미 생성한 문제 풀이·해설·기록은 유지한다. 학생의 기존 학습 결과를 결제로 막지 않는다.
- 구독 여부와 문제 준비 여부를 구분한다. 구독 성공을 문제 생성 성공으로 표시하지 않는다.

완료 확인: 무료 체험, 모의 구독, 두 번째 과목에도 같은 구독 적용, 중복 요청, 다른 계정 접근 차단, 제공량 소진, 기간 만료를 확인한다. 모의 구독은 결제대행사 테스트 결제나 실제 매출과 구분한다.

## 6. 사용자 흐름

1. 로그인하고 개인 과목을 만든다.
2. 이용 권한이 있는 PDF를 올리고 학습 준비를 누른다.
3. 서버가 개념과 첫 단계 5문제를 생성하는 동안 진행 상태를 확인한다.
4. 웹에서 첫 단계를 풀고 점수·해설·근거 페이지를 확인한다.
5. 틀린 문제를 다시 풀거나 새 회차에 도전한다.
6. 다음 단계에서 월 2,900원과 제공량을 확인하고 모의 구독을 시작한다.
7. 다음 단계의 문제 만들기를 누르고 생성된 문제를 이어서 푼다.

학교에서 제공받은 크레딧으로 개발 중 호출하더라도 상용 운영비가 사라지는 것은 아니다. 지원 종료 후 비용은 구독 매출로 부담하는 구조다.

## 8. 기술 구성

기술 목표는 Next.js·TypeScript·Tailwind, Supabase, Vercel이다. 현재 main의 Express 구현과 별도 Next.js 작업 브랜치가 있으므로 이 수정안 때문에 새로운 프레임워크 전환을 시작하지 않는다. 통합 담당이 실제 채택한 실행 구조를 기준 PRD와 일치시킨다. 웹과 생성 API 경로는 같은 프로젝트에서 실행한다. 라이브러리의 실제 버전과 지원 방식은 구현 시 확인하고 부록에 기록한다.

| 구성 | 책임 | 확인할 조건 |
| --- | --- | --- |
| 웹 | 자료 등록, 학습, 구독 화면 | 비밀값을 브라우저 코드에 넣지 않음 |
| 서버 | AI 호출·사용량 예약, 형식 검사, 접근 제어, 채점, 구독·기록 | 브라우저가 보낸 정답·가격·소유자를 신뢰하지 않음 |
| Supabase | 인증, 비공개 파일, 과목·문항·풀이 기록 | 다른 사용자 행과 파일 접근 차단 |
| 생성형 AI API | 근거를 읽고 개념·문항 생성 | 공급자·모델·입출력 토큰 상한·실패 동작·사용량 확인 |

주요 데이터는 사용자, 개인 과목, 자료·청크, 개념·선수 관계, 문항·근거, 풀이 회차·답안, 모의 주문·구독 기간, 생성 작업·사용량 예약이다. 과목과 문항에는 소유자를 둔다. 풀이 회차는 시작 시 문항 버전과 순서를 고정한다. 결과는 서버가 계산한다.

자료 상태는 업로드 중 → 분석 중 → 준비 완료 또는 실패다. 문항 상태는 사용 가능 또는 본인 제외다. 회차는 진행 중 → 제출 완료다. 구독은 없음 → 유효 → 만료다. 생성 작업은 대기 → 실행 중 → 성공 또는 실패다. 미완료 상태를 성공으로 표시하지 않는다.

원본 PDF는 다른 학생에게 배포하지 않는다. 이번 시연 자료는 팀이 작성한 자료 또는 이용 조건이 확인된 자료로 제한한다. 비공개 입력과 AI 생성만으로 권리 문제가 모두 해결됐다고 설명하지 않는다. 상용화 전 업로드·외부 AI 처리 권한, 보관·삭제 정책을 별도로 검토한다.

## 9. 비즈니스 모델과 검증

### 판매할 가치

판매 대상은 자료 원본이 아니라, 같은 과목의 학습 순서·문제·오답·진행 기록을 이어서 사용하는 경험이다. 첫 단계에서 이 가치를 체험한 학생이 나머지 범위도 같은 방식으로 공부하기 위해 결제한다는 가설이다.

구독 가격은 월 2,900원이며 실제 지불 의사는 미검증이다. 정해진 제공량 안의 AI 비용은 서비스가 부담한다. 무료 대안 대비 추가 가치를 설명하지 못하면 가격을 낮추는 것만으로 해결되지 않는다.

### 초기 유입과 반복 구매

초기 유입은 참여 동의를 받은 학과 스터디에서 시작한다. 처음에는 자료 업로드·문제 자동 생성 과정을 관찰하며 도움 없이 첫 문제를 푸는지 확인한다. 반복 구매는 다음 시험 또는 다른 과목에서 다시 쓰는지로 확인한다. 교수·업체 제휴를 이번 제출의 선행 조건으로 두지 않는다.

### 원가와 채산성

학생이 서비스에 월 구독료를 내고, 운영자는 AI 공급자에 API 사용료를 낸다. 플랫폼 원가는 개념·문항 생성의 입력 및 출력 토큰 비용, 실패·재시도, 저장소, 서버 실행, 전송, 인증, 운영·문의 대응 비용이다. 학생이 구독료를 낸다는 사실만으로 API 원가가 모두 충당되는 것은 아니다.

구독자 1명당 월 공헌이익은 월 실수취액에서 그 학생의 생성형 AI 호출·서버·저장·전송 비용과 변동 지원 비용을 뺀 값이다. 실제 판매 시 결제 수수료·세금·환불도 반영한다. 고정 운영비는 별도로 계산한다. 공급자 가격과 실제 사용량이 없으므로 이익률이나 예상 매출을 확정하지 않는다.

이번 자료·문항·요청 한도는 비용과 구현 범위를 제한하기 위한 제안값이다. PDF 한 개의 개념 추출과 5문항 생성 비용을 실제로 측정하고, 제공량을 모두 사용하는 경우와 재시도를 포함해 월 원가를 계산한다. 평균 사용량뿐 아니라 최대 제공량에서도 월 2,900원으로 지속 가능한지 확인해야 한다. 학교 크레딧은 개발 지원이며 반복 가능한 상용 원가 절감으로 계산하지 않는다. 다중 계정 무료 체험과 운영자 총지출 한도도 상용화 전에 점검한다.

| 첫 연동 후보 | claude-sonnet-5 | 품질 검사를 먼저 수행 |
| 요청당 입력 상한 | 12,000토큰 | 교안·지시·출력 형식을 포함한 전체 입력 |
| 요청당 출력 상한 | 2,500토큰 | 5문제와 짧은 해설, 장문 답변 억제 |
| 요청당 예산 예약 | 0.06 USD | 표시 단가 기준 최대 0.049 USD보다 여유 확보 |
| 동시 생성 | 계정당 1개, 전체 3개 | 중복·동시 호출 관리 |
| 재시도 | SDK 자동 재시도 0회, 명시적 재시도 최대 1회 | 재시도도 별도 예산 예약·횟수 차감 |
| 고가 모델 자동 전환 | 사용하지 않음 | 장애 때 비용이 급증하는 동작 방지 |

표시 단가 기준 계산은 `(12,000 × 2 + 2,500 × 10) / 1,000,000 = 0.049 USD`다. 이는 토큰 상한과 해당 요금이 실제로 지켜질 때 한 요청의 계산상 비용이며 실제 평균 비용이 아니다. 시연 예산 15 USD를 요청당 0.06 USD로 잡으면 예약 기준 250회다. 개념 추출·실패·재시도도 포함하므로 250명이나 1,250개의 완성 문제를 보장하는 수치가 아니다.

구독자의 기간당 40회 요청을 전부 상한까지 쓰면 AI 비용만 계산상 1.96 USD다. 이 최대 사용 시나리오는 월 2,900원 상품의 채산성을 위협할 수 있으므로 지금 제공량을 상용 확정하지 않는다. 월 2,900원에서 이 비용 외에 환율·세금·인프라·결제·지원 비용을 반영해야 한다. 생성 문항 150개를 항상 제공할 수 있는지도 40회 안에서 실제 검증한다. 공급자 장애로 제공량을 못 채우는 경우의 실제 환불 정책은 상용화 전 확정한다.

호출 최적화는 다음 순서로 적용한다.

1. PDF 원본을 매번 보내지 않고 추출한 페이지 텍스트를 저장한다. 개념은 한 번만 추출하고 각 5문제 생성에는 해당 근거 페이지와 필요한 개념 설명만 보낸다.
2. 요청 전체 토큰 수를 모델에 맞는 방법으로 계산한다. 문자 수를 토큰 수로 가정하지 않는다. 12,000토큰을 넘으면 범위를 나눠 달라고 안내하며 내용을 몰래 자르지 않는다. 학교 API의 토큰 계수 지원 여부는 실제 연동에서 확인한다.
3. 필요한 단계만 생성한다. 한 번에 모든 150문항을 생성하지 않는다. 같은 문항의 재풀이·채점·해설은 DB와 서버 규칙으로 처리한다.
4. 자료 해시·개념·프롬프트 버전·모델이 같은 완료 작업은 본인 계정 안에서 재사용한다. 중복 요청은 진행 중 작업을 반환한다. 다른 학생 자료를 비용 절약을 이유로 공유하지 않는다.
5. 출력은 정해진 JSON과 짧은 해설로 제한한다. 응답이 출력 상한 때문에 끊기면 실패로 기록한다. 오류를 숨기거나 무한 재생성하지 않는다.
6. 요청 전에 DB에서 전체 예산과 해당 단계 예산을 원자적으로 예약한다. 메모리 변수만으로 관리하면 Vercel의 여러 서버 실행 사이에서 한도가 어긋나므로 금지한다.
7. 성공 후 사용량으로 실제 비용을 정산한다. 타임아웃 등 청구 여부를 모르면 예약액을 유지하고 확인 후 정산한다. 지출과 예약의 합계가 중단선을 넘으면 새로운 생성만 중단하고 기존 풀이·해설은 유지한다.

학교 지갑·키 한도는 코드의 예산 제한과 별도로 확인한다. 기존 1달러 제한 키를 20달러라고 가정하지 않는다. 키 제한 변경·새 키 발급·Vercel 환경변수 등록·유료 호출은 이 문서 작성으로 실행되지 않았다. 20달러 예산은 승인된 사용 상한이지 이미 충전된 잔액의 확인 결과가 아니다.

Vercel CLI는 배포 수단이다. 학교 API 호출에 필요한 기본 주소는 `https://ai.cs.kookmin.ac.kr`이며 `/keys`는 관리 화면이다. 서버 설정은 `KMU_AI_BASE_URL`, `KMU_AI_API_KEY`, `KMU_AI_MODEL`로 통일하는 것을 제안한다. 이 이름들은 우리 앱의 설정 계약이며 SDK가 자동으로 인식한다고 가정하지 않는다. 키는 서버 전용 환경변수로 전달하고 로그·브라우저·Git에 넣지 않는다. Preview와 Production 환경을 구분하고 설정 후 새 배포에 반영한다. 근거: [Vercel 환경변수](https://vercel.com/docs/environment-variables), [Vercel CLI env](https://vercel.com/docs/cli/env).

설정 파일 [ai-budget.json](ai-budget.json)은 비밀값 없는 구현 입력안이다. 현재 앱에서 읽고 강제하는 코드가 연결된 것은 아니다. 클로드는 이 절과 설정 파일을 기준 설계에 먼저 통합한 뒤 API 호출과 DB 예산 예약을 구현해야 한다.

- 로컬 실행: 최종 채택한 브랜치의 package.json과 실행 결과로 확정한다. 현재 main의 Express 실행과 Next.js 작업 브랜치의 실행 명령은 서로 다르므로 혼용하지 않는다. 이 수정안에서는 깨끗한 복제 환경의 실행까지 검증하지 않았다.
- 실제 생성형 AI 연동: 미검증. 연결 성공 기록 확보 후 갱신한다.
- 기본 모델·요청 한도: 9절에 설정안을 기록했다. 실제 연동과 토큰 계수·원가 측정은 미검증이며 제공량의 수익성을 주장하지 않는다.
- 결제: 설계 범위는 모의 결제. 실제 구현 여부는 인수 검사 후 갱신한다.
- 사용자 수·매출: 확인 자료 없음. 예시 데이터를 실제 성과로 표시하지 않는다.
