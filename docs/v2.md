# PassFinder v2 — 문제와 랭킹

2026-10-03 사용자 요청으로 `/v2/`에 별도의 최소 학습 흐름을 구현했다. 기존 첫 화면, `/study/`, 결제·학습맵·운영 확인 화면과 독립적이다.

## 사용자 흐름

1. 문제 목록에서 시험 선택 또는 **문제 만들기**.
2. 텍스트 PDF(20MB 이하, 150쪽 이하)에서 최대 20쪽 선택하거나 교안 텍스트 붙여넣기.
3. 학교 AI가 객관식 5문제를 생성. 정답 근거가 입력 교안에 실제로 존재하는지 검사 후 서버에 저장.
4. 닉네임으로 참여 → 한 문제씩 풀이 → 제출 → 서버 채점(100점 만점).
5. 정답·해설·근거 및 같은 시험의 실제 랭킹 확인. 시험 링크로 다른 브라우저에서도 동일한 문제에 참여.

회원가입, 로그인, 결제, XP, 학습맵, 문제은행 선택, 운영용 버튼은 이 흐름에 포함하지 않는다. 기본 샘플 시험은 명시적으로 표시하며 가상의 참가자나 점수를 넣지 않는다.

## 저장과 비교 기준

- Supabase `AltTab` (`ltxuvtunctrayeewbwyd`)의 `alttab_v2_exams`, `alttab_v2_attempts`, `alttab_v2_generations`만 사용한다. `/tmp`나 브라우저를 공동 데이터 저장소로 사용하지 않는다.
- 닉네임은 표시 이름이며 실제 계정 인증이 아니다. 서버에서 발급하는 HttpOnly 쿠키의 SHA-256 해시로 같은 브라우저를 구분한다. 쿠키를 삭제하거나 다른 브라우저를 쓰면 별도 참가자가 될 수 있다.
- 시험별 첫 제출만 랭킹 반영. `(exam_id, participant_key)` 유일 제약, `result IS NULL` 조건부 갱신으로 동시·중복 제출에도 최초 결과가 고정된다.
- 같은 점수는 공동 순위(1, 1, 3). 같은 시험의 실제 제출만 비교하며 상위 50명을 표시한다. 상위 50명 밖에 있어도 본인 순위는 계산한다. 예상 학점/등수 모델은 없다.
- 정답·해설은 서버 저장소에만 있고 제출 전 응답에서 제외된다. 기존 임의 점수 입력 API는 v2 랭킹에 연결하지 않는다.
- PDF 원본과 전체 교안 텍스트는 저장하지 않는다. 문제·해설·짧은 근거 인용만 보존한다. 생성한 시험은 공개 목록과 공유 링크로 참여할 수 있음을 생성 화면에서 안내한다.
- 응시자의 닉네임·점수 공개를 시작 화면에 표시한다. 임시 답 선택만 localStorage에 보존한다.

## 서버 구성

- `v2.js`: 별도 Express 라우터와 서버 채점. `v2-store.js`: Supabase 접근. `v2-ai.js`: 학교 AI 연결과 교안 근거 검사.
- 기존 서버 환경 변수 `SUPABASE_KEY`, `KOOKMIN_KEY`를 사용한다. Supabase URL은 기존 AltTab 주소로 고정하며 다른 URL 설정은 거부한다. 키를 조회하거나 새로 발급하지 않는다.
- 학교 AI: `https://ai.cs.kookmin.ac.kr/v1/messages`, `x-api-key`, 모델 `claude-haiku-4-5`, 최대 출력 3,000토큰, 요청 제한 55초, 자동 재시도 없음.
- AI 입력: 제목 100자, 20쪽, 전체 40,000자, 공백 제외 200자 이상. 공급자 오류 원문은 브라우저에 반환하지 않는다.
- 문제 생성은 DB에서 먼저 요청을 기록한다. 같은 브라우저·교안의 완료된 요청은 재사용, 진행 중 중복 요청은 차단한다. 시험 저장과 생성 완료 표시는 한 DB 트랜잭션이다.
- 남용 완화: 전체 최근 24시간 50회, 브라우저별 최근 1시간 3회. 실패·시간 초과도 횟수에 포함. 호출·토큰 제한이며 금액 상한은 아니다. `/mock/`의 별도 제한과 데이터는 변경하지 않는다.
- 모든 v2 테이블에 RLS 활성화. `anon`/`authenticated` 직접 접근·함수 실행 권한 없음. 서버 역할만 허용하고 함수는 `SECURITY INVOKER`. 서버는 필요한 공개 필드만 반환한다.
- DB 장애를 로컬 저장 성공으로 표시하지 않는다. 시험·점수 쓰기는 DB 성공 응답 뒤에만 완료 표시.

## API

| 경로 | 역할 |
|---|---|
| `GET /api/v2/exams` | 최신 시험 목록(최대 100개), 생성 기능 설정 여부 |
| `POST /api/v2/exams` | 교안으로 문제 생성·검증·저장 |
| `GET /api/v2/exams/:id` | 정답 제외 문제, 현재 브라우저의 기존 응시/결과 |
| `POST /api/v2/exams/:id/start` | 닉네임으로 최초 응시 시작 또는 재개 |
| `POST /api/v2/exams/:id/submit` | 서버 채점 후 최초 결과 고정 |
| `GET /api/v2/exams/:id/ranking` | 해당 시험 순위, 참가자 수, 본인 순위 |

## 구현 시 검증

검사 데이터의 SQL 줄바꿈은 읽을 때 LF로 정규화한다. Windows와 Linux에서 같은 샘플 문항을 읽으며 운영 SQL과 서버 동작은 변경하지 않는다.

- `node --test tests/v2.test.cjs tests/exam-workspace/http.test.mjs` 통과. 답/해설 비공개, 서버 채점, 다른 쿠키의 결과 격리, 중복 시작·제출, 공동 순위, 시험별 분리, 생성 재사용, 근거 실패·공급자 오류 처리를 검사했다.
- 실제 Supabase 트랜잭션에서 공동 순위, 유일 제약, 조건부 결과 갱신, 생성 claim/중복/할당량, 원자적 저장, 익명 권한 차단 검사 통과 후 롤백했다. 검증용 참가자는 남기지 않았다.
- Supabase 보안 advisor: 경고/오류 없음. RLS 정책 없음 INFO는 서버 전용 테이블 설계에 따른 것이며 공개 정책을 추가하지 않았다.
- 로컬 브라우저: PDF 텍스트 추출 → 5문제 생성 연결(이 단계의 AI는 명시적 테스트 fixture), 4정답·80점 → 해설 → 랭킹 → 새로고침 기록 유지 통과. 390px 화면 가로 넘침 없음, 브라우저 오류 없음.
- 로컬 프리뷰는 `node tests/v2-preview.cjs`. 테스트 저장소와 가짜 AI는 이 전용 실행 파일에서만 주입되며 `server.js`에서는 사용하지 않는다.

- 구현 커밋 `4b3aeb0a78430b9f7666916f9947548c49e77cc9` 및 생성 실패 안내 보강 `2630b7b53bd637374e749d4346cc2b9e9661929f`의 Vercel 배포 성공. 실제 주소는 https://alt-tab-mu.vercel.app/v2/.
- 직접 작성한 자료구조 교안으로 학교 AI를 2회 호출했다. 첫 응답은 문제 검증 실패로 저장되지 않았고, 재시도에서 원문 근거를 통과한 5문항이 생성·저장됐다. 실패 원인은 형식/출력 중단/문항 검증으로 구분해 안내하며 원본 공급자 응답은 노출하지 않는다.
- 브라우저에서 AI 생성 시험 응시 → 4정답·80점 → 정답/해설/교안 인용 → 같은 시험 랭킹 표시를 확인했다.
- 운영 HTTP 요청으로 정답 비공개, 위조 점수 무시, 최초 제출 결과 고정, 다시 조회한 결과 유지, 서로 다른 쿠키 간 결과 격리와 공동 랭킹 조회를 확인했다.
- 검증용 응시 기록 2개는 검사 후 삭제했다. 자료구조 교안으로 만든 정상 시험은 바로 풀 수 있도록 남겼으며, 가상 참가자나 가상 점수를 초기 데이터로 남기지 않았다.
