# passfinder 공통시험 구현 지시

아래 내용을 Claude Code에 전달한다. 정본은 main의 [passfinder PRD](../passfinder-prd.md)이며, 이 지시문은 별도 PRD가 아니다. UI 담당자는 따로 있으므로 이 작업은 서버와 DB에 한정한다.

```text
최신 main의 passfinder-prd.md를 먼저 읽고 그대로 구현해줘. 이번 작업은 “같은 시험을 푼 학생들의 결과 비교와 풀이 참고”다.

작업 경계
- 저장소·브랜치·미커밋 변경을 확인하고, 별도 worktree에서 작업한다. 다른 Claude의 변경을 덮지 않는다.
- 현재 Express 서비스에 연결한다. Next.js 전환·배포 교체·새 Supabase 프로젝트 생성·브랜딩·발표 기획을 다시 하지 않는다.
- UI 파일(index.html, public/**, 화면 스타일·문구·버튼)을 수정하지 않는다. UI 담당자에게 줄 API 요청·응답 예시와 연결 순서만 docs/api-contract.md에 정리한다.
- 기존 Supabase와 학교 AI 환경 설정을 사용한다. 키와 .env 값은 Git·로그에 넣지 않는다.
- 관련 설계에 필요한 변경을 먼저 반영하고 구현한다. PRD 사본을 만들지 않는다.

구현할 것
1. c7b06b7의 POST /api/question-sets, POST /api/question-sets/:setId/attempts, POST /api/attempts/:attemptId/answers를 먼저 읽고 재사용한다. 이미 세트 저장·정답 제외 출제·서버 채점이 있으니 다시 만들지 않는다. 로컬 JSON 저장을 기존 Supabase의 shared_exams·shared_attempts로 연결하고 시험 식별자·버전을 유지한다. 공유 식별자와 API 계약을 제공하며 공유 화면은 UI 담당자가 만든다. 기존 정답 JSON 공개 접근 차단도 유지한다.
2. 정답·해설은 서버에 보관하고 제출 전 브라우저에 보내지 않는다. 클라이언트는 문항별 답안만 보내고 서버가 채점한다. 기존 scores.js의 클라이언트 점수 신뢰 방식과 시험 구분 없는 조회를 그대로 연결하지 않는다.
3. 익명 닉네임과 별도로 참가자 세션·응시 식별값을 서버가 발급한다. 본인 응시만 제출하고 중복 요청은 한 번만 반영한다. 같은 참가자·시험·버전의 첫 완료 응시만 집계하며 재응시는 연습으로 둔다.
4. 동일 시험·버전의 참가자 수, 평균, 문항별 정답률, 공동 순위를 계산한다. 순위는 “내 점수보다 높은 참가자 수 + 1”이다. 정답을 아는 시험 작성자는 순위에서 제외하고 이유를 표시한다. 0명은 빈 상태, 1명은 비교 대상 부족으로 표시한다. 익명 참가 기록 기준임을 밝히고 예상 학점·시험 점수를 만들지 않는다.
5. 제출 후 AI 공통 해설과 학생 풀이를 구분하는 API를 만든다. 학생이 자발적으로 공유한 300자 이내 풀이만 본인 응시에 저장하고 같은 시험 제출자에게 반환한다. 작성자만 수정·공유 취소하도록 한다. 일반 텍스트임을 API 계약에 명시하고 채팅·댓글·좋아요는 만들지 않는다.
6. 재접속·서버 재시작 뒤에도 시험과 결과를 DB에서 읽는다. DB 실패를 성공으로 표시하지 않는다.

비용
- 학생의 개인 AI 연결 설정 없이 사용하게 한다. 학교 AI 키는 서버에서만 사용한다.
- 예산은 총 20달러다. 문제·해설을 재사용하고 조회·채점·통계·풀이 저장에 새 LLM 요청을 만들지 않는다. API 시험은 현재 사용량을 확인해 최소화한다.

반드시 확인할 것
- 독립적인 두 참가자 세션으로 같은 시험을 풀어 다른 답에 맞는 서버 점수와 함께 집계된 결과를 API에서 확인한다. 화면 연결 확인은 UI 담당자와 분리한다.
- 다른 시험·다른 버전의 결과는 섞이지 않는다. 동점·0명·1명·미응답·작성자 제외가 정책과 일치한다.
- 임의 점수나 다른 참가자 식별값을 보내도 점수 조작·대리 제출이 안 된다. 중복 제출·응답 유실 후 재시도가 이중 집계되지 않는다.
- 제출 전 정답 비공개, 제출 후 해설·학생 풀이 구분, 재접속·서버 재시작 뒤 DB 보존을 확인한다.
- 관련 테스트와 실제 DB 저장·재조회를 확인한다. UI 통합과 배포에서 확인하지 못한 항목은 미완료로 남기고 UI 파일을 대신 고치지 않는다.

고친 설계서·코드, 실제 확인 결과, 남은 문제를 보고해줘. 검증 후 원격 main의 최신 변경과 동기화하고 일반 커밋·push까지 마쳐줘. 다른 작업을 덮거나 force push하지 마. 동기화·검증·push가 실패하면 원인을 보고하고 완료로 처리하지 마.
```
